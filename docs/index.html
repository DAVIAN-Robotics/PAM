Abstract

Proactive robots should anticipate user needs and provide assistance before being explicitly asked. A straightforward approach is to infer human intentions from commonsense knowledge, but the same observed behavior can imply different needs across users, potentially leading to unwanted assistance. We observe that everyday routines in the real world exhibit recurring patterns, so learning these patterns can reduce ambiguity in proactive decisions. Based on this, we propose a memory-based agentic framework in which a VLM task predictor reads a Procedural Assistance Memory (PAM) alongside the current observation to decide when to assist and what task to perform, and a VLA executor performs the predicted task. PAM is structured as a finite-state machine over activity phases, per-state assistance rules, and event-driven transitions; a reflection VLM revises PAM from each day's interaction trace without weight updates or retraining. In our 5-day desk-assistance evaluation, memory-free baselines remain conservative, with limited recall on proactive tasks. Our system improves consistently with accumulated experience, achieving the highest precision, recall, and F1 and reducing first-fire delay from approximately 5 seconds on Day 1 to 1 second by Day 5. Our approach also adapts to changes in the user's routine through continued memory reflection, recovering from memory–routine misalignment after a single memory update.

The Same Behavior, Different Needs

Visually similar observations map to different correct actions depending on user-specific habits. PAM resolves this ambiguity by conditioning the task predictor on accumulated behavioral context.

A useful assistant does not only respond to requests. It hands over an object at the right moment, puts an item away after it has been used, and prepares what will be needed next. Recent work splits a robot into a high-level VLM that decides when and what to help with and a VLA that executes the chosen atomic task. This split puts the whole burden of proactivity on the high-level VLM.

Zero-shot intention prediction breaks down when the same observable behavior means different things for different users: one person setting out a mug wants coffee, another wants hot water for tea. The missing information is not in the scene but in the user's habits. That information can be learned during deployment. Everyday behavior is highly repetitive, so a handful of past interactions already reveals stable preferences, and a correction given once can be reused every time the situation recurs.

Method

(a) A VLM task predictor reads PAM and recent frames to select assistive tasks for the VLA executor. (b) At the end of each day, a VLM memory reflector updates PAM from the day's video by adding or revising states, trigger–action pairs, and transitions.

Real-time task prediction and execution

The task predictor (Qwen3.5-27B, thinking off) serves as System 2. Once per second it receives the latest W = 5 frames, PAM as text, and one fixed instruction, "Proactively help the user before they ask." Using the routine stored in PAM to interpret what it sees, it outputs either a task in natural language or NO_ACT. The predicted task goes to a π0.5 executor, which serves as System 1 and generates the robot actions. For example, as the user pours cereal, the predictor selects "bring milk", and the executor picks up the milk and places it next to the user.

Procedural Assistance Memory (PAM)

The simplest memory is a flat list of trigger–action pairs, but a list gives little context for reading a cue. An empty bowl on the desk can mean "bring cereal" when the user is about to eat, or "put the bowl away" when they have finished.

PAM therefore takes the form of a finite-state machine. States describe activity phases, per-state trigger–action pairs link cues to assistive tasks, and transitions capture the observable events between phases, such as picking up a spoon to move from meal preparation to eating. A trigger fires before the user starts an action the robot can do for them: when the user sits down holding an empty bowl, the robot brings cereal before the user fetches it.

An example of PAM: states, trigger–action pairs, and transitions.

Offline memory reflection and update

At the end of each day, a memory reflector (the same backbone, thinking on) updates PAM. It reads sampled frames from the day's video, the previous PAM, a summary of the day's action history, and user feedback when available. The recording also contains the things the user did without help, so the reflector can spot missed opportunities: seeing the user bring out an empty bowl and then pour cereal, it infers that the robot should bring cereal when an empty bowl appears. It adds such rules and revises states, rules, or transitions when the routine changes. PAM stays fixed during the day, and all adaptation happens through these nightly revisions, with no weight updates or retraining.

Experimental Setup

We evaluate on a morning desk routine. The user arrives carrying an empty bowl, sits down, pours cereal and then milk, and eats breakfast. Afterwards they set the bowl aside, work on a laptop, wipe their mouth with a wet wipe, leave the used wipe on the desk, and eventually leave. The robot is never told which task to do or when. It must perform six proactive tasks, some preparing items for the next step and some clearing items after use, so the same object can call for different actions as the routine progresses.

Proactive Prediction across Memory Designs

Multi-day proactive task prediction (Days 1–5). Memory-free baselines show limited T1–T6 recall, while Ours (FSM Memory) improves every day, reaching the highest F1 and cutting first-fire delay from about 5 s on Day 1 to about 1 s by Day 5.

Memory is what lets the robot act. Without knowledge of the user's routine, LIT, Event-Driven, and the Zero-shot VLM fall back on NO_ACT whenever the scene is ambiguous. LIT and Event-Driven rarely fire any proactive task, and the Zero-shot VLM plateaus from Day 2 onward. All three stay essentially flat across the five days: without memory, repeated exposure does not turn into better proactive behavior.

The FSM structure is what keeps it improving. List Memory saturates early, because a flat list offers no abstraction over recurring states as it grows. FSM Memory improves on every day and achieves the highest precision, recall, and F1 on T1–T6, so the gain comes from the structure itself and not just from adding memory. The cost is some eagerness: FSM Memory's NO_ACT recall is lower than the conservative baselines', although its higher NO_ACT precision keeps NO_ACT F1 on par.

Adapting When the Routine Changes

When a user's routine changes, previously learned rules can become wrong, so the memory must adapt quickly. We take a user who has followed the cereal routine (Scenario A) for five days and switch them to a different routine (Scenario B): they arrive empty-handed, take vitamins with water, and drink a Coke while working on the laptop.

Scenario B, the vitamin routine.

Memory adaptation (Scenario A→B). A-Frozen keeps A's Day-5 memory unchanged; A-Evolving starts from the same memory and keeps reflecting each day on B. Scratch-Evolving builds a memory from scratch on B; the Zero-shot VLM uses none.

On Day 1 the old memory confuses the predictor: A-Evolving has lower task recall and F1 than the Zero-shot VLM. After a single reflection at the end of Day 1, it reaches the level of Scratch-Evolving on Day 2 and stays close for the rest of the week, while A-Frozen stays below the Zero-shot VLM. First-fire delay also keeps dropping with continued reflection. PAM recovers from the mismatch after one memory update, without wiping the memory or retraining any model.

Watch the Memory Write Itself

Each night the reflector reads the day's recording and edits PAM. From Day 3 to Day 5, missing trigger–action pairs are recovered (for example, "person pours cereal" → "milk to person"). When the routine changes, the reflector rewrites the affected rule: "person sits down" → "cereal to person" becomes "vitamin to person". An end-to-end model must learn robot actions and VLM-style reasoning together, and with limited data it does neither well. Milk→Storage, which needs a grasp on the rounded milk cap, is never achieved by either monolithic variant: a single prompt across all six tasks leaves no capacity to specialize. The reasoning variant suffers most. Even with frame-level subtask supervision, it often reasons wrongly: when the right move is Cereal→Storage but the user happens to hold the milk, the visible milk pulls it toward Milk→Storage, and the wrong reasoning makes the action fail too. Our framework leaves atomic actions to π0.5 and reasoning to Qwen3.5, and wins on both.

Conclusion

PAM is an FSM-based memory that personalizes proactive robot assistance through daily reflection, without weight updates. Over five evaluation days it improves both proactive prediction and response timing, and its structure lets it adapt when the user's routine changes. The FSM structure and continued reflection each contribute, and the System 1–2 decomposition executes tasks more reliably than monolithic VLAs.

Limitations. FSM Memory sometimes fires when the user briefly handles a learned trigger object without committing to that step; in such ambiguous moments the right behavior is often to ask, which our framework does not yet do. Our evaluation is also limited to seen scenarios rather than novel objects, layouts, or users, a constraint set by the capacity of current open-source VLAs.
