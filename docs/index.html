Abstract

Proactive robots should anticipate user needs and provide assistance before being explicitly asked. A straightforward approach is to infer human intentions from commonsense knowledge, but the same observed behavior can imply different needs across users, potentially leading to unwanted assistance. We observe that everyday routines in the real world exhibit recurring patterns, so learning these patterns can reduce ambiguity in proactive decisions. Based on this, we propose a memory-based agentic framework in which a VLM task predictor reads a Procedural Assistance Memory (PAM) alongside the current observation to decide when to assist and what task to perform, and a VLA executor performs the predicted task. PAM is structured as a finite-state machine over activity phases, per-state assistance rules, and event-driven transitions; a reflection VLM revises PAM from each day's interaction trace without weight updates or retraining. In our 5-day desk-assistance evaluation, memory-free baselines remain conservative, with limited recall on proactive tasks. Our system improves consistently with accumulated experience, achieving the highest precision, recall, and F1 and reducing first-fire delay from approximately 5 seconds on Day 1 to 1 second by Day 5. Our approach also adapts to changes in the user's routine through continued memory reflection, recovering from memory–routine misalignment after a single memory update.

Introduction

Visually similar observations map to different correct actions depending on user-specific habits, and our PAM memory resolves this ambiguity by conditioning the task predictor on accumulated behavioral context.

A truly useful assistant in everyday life does not only respond to requests, but also anticipates when help would be valuable. Recent work has adopted a System 1–2 design that explicitly separates a high-level reasoning module from a VLA that executes atomic tasks. We adopt this structure, which in turn places the burden of proactivity squarely on the high-level VLM.

Zero-shot prediction remains unreliable when the same observable behavior corresponds to different desired outcomes across users: one person setting out a mug wants coffee, another wants hot water for tea. A fixed, pretrained predictor cannot resolve such ambiguity, because the missing information is not in the scene but in the individual user's habits.

Crucially, this missing information can be learned during deployment. In housekeeping settings, an individual's behavior is highly repetitive, so even a handful of past interactions reveal stable preferences, and corrective feedback gathered once can be reused whenever a similar situation recurs. To this end, we introduce Procedural Assistance Memory (PAM), a continually updated deployment-time memory that records when assistance is needed and what assistive task should be issued for a particular user.

Method

Our goal is to learn and store a user's routine in memory, then use it to decide when to assist and what task to perform in real time. The system should also adapt quickly to routine changes without retraining.

(a) A VLM task predictor reads PAM and recent frames to select assistive tasks for the VLA executor. (b) At the end of each day, a VLM memory reflector updates PAM from the day's video by adding or revising states, trigger-action pairs, and transitions.

Real-Time Task Prediction and Execution via System 1–2 Architecture

Our task predictor serves as System 2, selecting assistive tasks without task-specific user instructions. At each 1-Hz step, it receives the latest W video frames, PAM as text, and the fixed instruction, "Proactively help the user before they ask." It uses the routine stored in PAM to interpret the observations and outputs either a task expressed in natural language or NO_ACT.

The predicted task is passed to the VLA executor, which serves as System 1 and generates low-level robot actions. For example, the predictor selects "bring milk" as the user pours cereal. The executor then carries out this task by picking up the milk and placing it next to the user.

Procedural Assistance Memory (PAM)

The simple solution is a flat list of trigger–action pairs, but this provides limited context for interpreting cues within the user's routine. For example, an empty bowl on the desk may indicate that the robot should bring cereal when the user is about to eat or put the bowl away when they have finished eating.

To reduce this ambiguity, we organize PAM using a finite-state-machine (FSM) structure: states describe activity phases, per-state trigger–action pairs link cues to assistive tasks, and transitions specify the events that connect phases. Transitions capture observable changes in the activity; for instance, picking up a spoon indicates the shift from meal preparation to eating. A trigger should occur before the user begins an action that the robot can perform for them.

An example of PAM, comprising states, trigger–action pairs, and transitions.

Offline Memory Reflection and Update

At the end of each day, a memory reflector updates PAM offline with reasoning enabled. It receives sampled frames from the day's video, the previous PAM as text, a summary of the day's action history, and user feedback when available.

The recording includes actions that the user performed without robot assistance. The reflector examines these segments to identify missed opportunities and infer recurring patterns. For example, seeing the user bring out an empty bowl and then pour cereal can lead it to infer that the robot should bring cereal when the user brings out an empty bowl. It adds the resulting assistance rule to PAM and revises existing states, rules, or transitions when observations or feedback indicate a change in the routine. PAM remains fixed during each day; adaptation occurs through these daily revisions.

Experimental Setup

We evaluate proactive assistance in a morning desk routine. The user arrives at the desk carrying an empty bowl, sits down, pours cereal and then milk into the bowl, and eats breakfast. After eating, the user sets the empty bowl aside and starts working on a laptop, then wipes their mouth with a wet wipe, leaves the used wipe on the desk, and eventually leaves the desk. To assist the user throughout this routine, the robot must perform six proactive tasks. The tasks include both preparing items for the user's next activity and clearing items after use. Thus, the same objects can require different robot actions as the routine progresses, making the timing of assistance part of the task.

Evaluation protocol. We formalize proactive task prediction as a per-frame classification problem. Importantly, the label set comprises not only the six tasks above but also a NO_ACT class indicating that no assistance is needed. We report precision, recall, and F1 score per class along with their macro averages. We also report the first-fire delay, measured from the time at which proactive assistance should be provided until the model first predicts the corresponding task. We conduct a multi-day evaluation over 5 days, in which the PAM persists across days and is updated from feedback from previous days.

Implementation details. We use Qwen 3.5 as the VLM for both the task predictor and the reflector. The task predictor runs with thinking mode disabled to support timely assistance. At each prediction step, it predicts a task or NO_ACT from a window of W=5 frames sampled at stride 2 from the 1 fps stream. For the executor, we collect 10 demonstrations per task and use them to finetune π0.5.

Baselines.

  • LIT. Builds a task graph over detected objects and estimates the current progress along the graph to predict the next task.
  • Event-driven VLM. Predicts the next task only when a scene change is detected via optical flow, by comparing the pre- and post-change frames.
  • Zero-shot VLM. A state-of-the-art VLM that predicts the next proactive task directly from the current observation, without any adaptation.
  • Ours w/ List Memory. A variant of our framework that replaces the FSM-structured memory with a flat list of trigger-action pairs accumulated over deployment, while keeping the rest of the pipeline identical.

Proactive Prediction across Memory Designs

Multi-day proactive task prediction (Days 1–5). Memory-free baselines show limited T1–T6 recall overall, while Ours (FSM Memory) consistently improves across days, achieving the highest F1 and reducing first-fire delay from ~5 s on Day 1 to ~1 s by Day 5.

Effectiveness of Memory. Baselines without memory (LIT, Event-Driven, Zero-shot VLM) predict conservatively: lacking prior knowledge of the user's routine, they default to NO_ACT whenever the observation is ambiguous, which inflates NO_ACT recall but suppresses proactiveness on T1–T6. LIT and Event-Driven rarely fire any proactive task, yielding near-zero recall, and the Zero-shot VLM plateaus from Day 2 onward with no mechanism to internalize recurring patterns.

Ablation of Memory Design. Ours w/ List Memory saturates early, since the flat list offers no abstraction over recurring states as it grows. In contrast, Ours w/ FSM Memory consistently improves across days, achieving the highest precision, recall, and F1 on T1–T6 while reducing first-fire delay from roughly 5 seconds on Day 1 to about 1 second by Day 5. This shows that the gains come from the FSM structure itself, not simply from adding memory. The trade-off is that FSM Memory's eagerness to act lowers its NO_ACT recall relative to the conservative baselines, although a correspondingly higher NO_ACT precision keeps its NO_ACT F1 on par with the others.

Adaptation to Routine Changes

When a user's routine changes, previously learned assistance rules may become inappropriate, making rapid adaptation important. Our method addresses this by updating PAM through reflection without retraining the models. We refer to the cereal routine as Scenario A. Scenario B involves a different routine. For example, the user takes vitamins instead of eating cereal. We evaluate how effectively and quickly PAM adapts over five target days when a user who has followed Scenario A suddenly switches to Scenario B.

A different routine (vitamin scenario). The user takes vitamins with water and drinks Coke while working on the laptop. The six assistance tasks involve delivering needed items and clearing them after use.

Memory adaptation (Scenario A→B). A-Frozen fixes A's Day-5 memory, while A-Evolving updates it at the end of each day in Scenario B. Scratch-Evolving builds memory from scratch on B; Zero-shot VLM uses no memory.

On Day 1, A-Evolving has lower task recall and F1 than the Zero-shot VLM, suggesting that memory from the previous routine can initially cause confusion in predicting proactive tasks in the new scenario. After a single reflection at the end of Day 1, however, its recall and F1 reach levels comparable to Scratch-Evolving on Day 2. They remain close over the subsequent days, while A-Frozen stays below the Zero-shot VLM. First-fire delay also decreases with continued reflection. These results show that PAM can quickly adapt an existing memory to a different routine, recovering from the initial mismatch after one memory update.

  • π0.5 (Reasoning). We finetune it with "Proactively help the user before they ask." as the high-level prompt and the corresponding atomic command as the low-level task, leveraging its reasoning capability.

Task-wise success rate comparison with monolithic VLA with and without subtask reasoning.

π0.5, with or without reasoning, suffers from lower success rates on the atomic tasks themselves, since the end-to-end model is forced to jointly learn robot actions and VLM-style reasoning. For example, Milk→Storage is among the harder atomic skills, as it requires grasping the rounded milk cap; π0.5 trained with a single prompt across all tasks lacks the capacity to specialize on such individual skills.

This degradation is especially pronounced in the reasoning variant under our low-data regime. For instance, when the correct prediction is Cereal→Storage but the user happens to be holding the milk, the visible milk often misleads the model into reasoning Milk→Storage, and such reasoning errors in turn make the generated action even more likely to fail. In contrast, our framework delegates atomic action generation to the strong pretrained π0.5 backbone and offloads reasoning to Qwen 3.5, achieving higher accuracy on both axes.

Conclusion

We introduced Procedural Assistance Memory (PAM), an FSM-based memory that personalizes proactive robot assistance through daily reflection without weight updates. Across five evaluation days, PAM improves proactive prediction and response timing, while its structured memory adapts to changes in the user's routine. Ablations demonstrate the benefits of FSM structure and continued reflection, and the System 1–2 decomposition improves task execution over monolithic VLAs.

Limitation. FSM Memory occasionally fires when the user briefly handles a learned trigger object without committing to that step, which lowers its NO_ACT recall; in such genuinely ambiguous situations the right behavior is often to ask the user rather than to act, but soliciting clarification lies outside our current framework. Due to the limited capacity of current open-source VLAs, our evaluation is restricted to seen scenarios rather than novel objects, layouts, or users.
