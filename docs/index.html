Abstract

Proactive robots should anticipate user needs and provide assistance before being explicitly asked. A straightforward approach is to infer human intentions from commonsense knowledge, but the same observed behavior can imply different needs across users, potentially leading to unwanted assistance. We observe that everyday routines in the real world exhibit recurring patterns, so learning these patterns can reduce ambiguity in proactive decisions. Based on this, we propose a memory-based agentic framework in which a VLM task predictor reads a Procedural Assistance Memory (PAM) alongside the current observation to decide when to assist and what task to perform, and a VLA executor performs the predicted task. PAM is structured as a finite-state machine over activity phases, per-state assistance rules, and event-driven transitions; a reflection VLM revises PAM from each day's interaction trace without weight updates or retraining. In our 5-day desk-assistance evaluation, memory-free baselines remain conservative, with limited recall on proactive tasks. Our system improves consistently with accumulated experience, achieving the highest precision, recall, and F1 and reducing first-fire delay from approximately 5 seconds on Day 1 to 1 second by Day 5. Our approach also adapts to changes in the user's routine through continued memory reflection, recovering from memory–routine misalignment after a single memory update.

The same scene, a different right answer

A person sits down with an empty bowl. Oatmeal? Cereal? Yogurt? Nothing in the scene settles it — the answer lives in the user's habits, not in the pixels. A zero-shot VLM, unable to tell which of several plausible interventions is the right one, does the safe thing and does nothing. That conservatism runs deep: LIT and Event-Driven rarely fire on any proactive task, at near-zero recall throughout the five days. The Zero-shot VLM does fire more often, but it plateaus from Day 2 onward — five days of repeated exposure to the same routine never sharpens it further.

The missing information is learnable, and cheaply. Everyday routines repeat, so a handful of days of watching one person is enough to fix what "a bowl on the desk" means for this person. PAM accumulates exactly that, at deployment time, with no weight updates.

Architecture

System 1–2, split. Once per second, a Qwen3.5-27B task predictor (thinking off) reads the PAM memory together with the last W = 5 frames and emits either a language subtask — "bring milk" — or NO_ACT. Anything that is not NO_ACT goes to a π0.5 executor fine-tuned on the six atomic skills, which turns it into robot action. Neither model has to do the other's job, which is exactly the failure mode of a monolithic VLA under limited robot data.

The memory writes itself. At the end of each day, a reflector — the same backbone, thinking on — reads sampled frames from the day's recording, a summary of the day's action history, and user feedback when available, and rewrites PAM: adding the assistive opportunities the robot missed, broadening triggers that fired too late, introducing new states, and revising rules that no longer match what the user does. No gradients, no retraining, no human writing rules.

A Franka Research 3 arm and three RealSense cameras. The VLM stack sees only the two back-facing views; the VLA additionally sees the wrist camera.

Six Proactive Tasks

The six tasks form one continuous desk routine. The robot is never told which one to do, or when — it is given a single fixed prompt, "Proactively help the user before they ask.", and must decide the rest.

The six tasks are not independent demos. They form one continuous desk routine, in the order a single morning actually unfolds — which is what makes knowing when to act as hard as knowing what to do.

Results

Memory-free baselines stay flat: with no knowledge of the routine they fall back on NO_ACT whenever the scene is ambiguous. LIT and Event-Driven rarely fire any proactive task, and the Zero-shot VLM plateaus from Day 2 onward. Our FSM memory climbs every day, reaching the highest precision, recall, and F1, and the robot fires sooner as it goes — first-fire delay falls from about 5 seconds on Day 1 to about 1 second by Day 5. A flat list memory improves too, but saturates early.

Having a memory is not the point — keeping it up to date is. A memory frozen after Day 1 beats the zero-shot VLM once it exists, but it never learns anything new and its first-fire delay plateaus near 2 seconds. Only the self-evolving memory keeps improving, reaching the highest final precision, recall, and F1.

Memory helps most exactly where the scene is not enough: T2 (Milk→Person) and T3 (Cereal→Storage), where what to do next depends on this user's habitual pairing rather than on anything visible. The FSM's lead over a flat list is largest on the put-away actions, T3 (Cereal→Storage) and T4 (Milk→Storage): organizing rules by activity phase tells the predictor when it is time to put items away.

Does It Only Work on One Routine?

A different routine, with almost no cues

In the desk routine, an empty bowl is a strong hint. So we built a routine that offers almost none: the user arrives empty-handed, takes vitamins with water, then drinks a can of Coke while working on the laptop before leaving. The robot is responsible for six tasks: deliver the vitamins, deliver the water, return the vitamin bottle, return the water bottle, deliver the Coke, and discard the empty can. Nothing on the desk says what comes next — which is precisely the knowledge a memory is supposed to supply.

The FSM memory still improves precision, recall, and F1 from Day 1 to Day 5, cutting first-fire delay from roughly 17 seconds to about 10. List Memory and the memory-free baselines show limited improvement.

What if the user's routine changes entirely?

A user who has followed the cereal routine (Scenario A) for five days suddenly switches to the vitamin routine (Scenario B). A-Frozen keeps the Day-5 memory from Scenario A unchanged; A-Evolving starts from the same memory but keeps reflecting at the end of every day in Scenario B. We compare both against Scratch-Evolving, which builds a memory from scratch on B, and the Zero-shot VLM, which uses no memory.

Scenario A→B. On Day 1 the old memory confuses the predictor: A-Evolving falls below the Zero-shot VLM in recall and F1. After a single reflection at the end of Day 1, it reaches the level of Scratch-Evolving on Day 2 and stays close for the rest of the week, while A-Frozen stays below the Zero-shot VLM throughout. First-fire delay also keeps dropping with continued reflection.

The reverse direction, Scenario B→A. B-Frozen again performs worse than the Zero-shot VLM, whereas B-Evolving approaches Scratch-Evolving by Day 3. A deployed robot does not need its memory wiped when the user's life changes.
